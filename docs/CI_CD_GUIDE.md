# 📚 Что такое CI/CD и GitHub Actions

Простое объяснение для начинающих разработчиков.

---

## Что такое CI/CD?

**CI/CD** — это практика автоматизации процессов разработки программного обеспечения.

- **CI (Continuous Integration)** — Непрерывная интеграция
- **CD (Continuous Delivery/Deployment)** — Непрерывная доставка/развёртывание

### Простыми словами

Представьте, что вы пишете код и хотите убедиться, что он:
- ✅ Работает корректно
- ✅ Не содержит ошибок
- ✅ Соответствует стандартам качества
- ✅ Не сломал существующий функционал

Вместо того чтобы проверять всё это вручную каждый раз, CI/CD делает это **автоматически** при каждом изменении кода.

---

## Что такое GitHub Actions?

**GitHub Actions** — это встроенный в GitHub инструмент для автоматизации задач.

Когда вы:
1. Пушите код в репозиторий (делаете `git push`)
2. Создаёте Pull Request
3. Делаете коммит в определённую ветку

GitHub Actions автоматически запускает набор проверок, тестов и других задач.

## Что делает наш CI/CD pipeline?

### 1. **Тестирование** (`test`)

- Запускает код на разных версиях Python (3.8, 3.9, 3.10, 3.11)
- Проверяет, что код работает корректно
- Запускает unit-тесты из `test_improvements.py`
- Проверяет покрытие кода тестами

**Зачем?** Убедиться, что код работает на всех поддерживаемых версиях Python.

### 2. **Линтинг** (`lint`)

- **Black** — проверяет форматирование кода (отступы, пробелы, стиль)
- **isort** — проверяет правильность сортировки импортов
- **flake8** — находит синтаксические ошибки и плохие практики
- **pylint** — углублённая проверка качества кода

**Зачем?** Поддерживать единый стиль кода, легко читаемый для всех разработчиков.

### 3. **Безопасность** (`security`)

- **safety** — проверяет зависимости на известные уязвимости
- **bandit** — ищет проблемы безопасности в коде (SQL injection, XSS и т.д.)

**Зачем?** Предотвратить использование небезопасных библиотек или паттернов кода.

### 4. **Сборка** (`build`)

- Проверяет, что все модули импортируются корректно
- Создаёт архив с артефактами (готовым кодом)
- Готовит код к развёртыванию

**Зачем?** Убедиться, что проект можно успешно собрать и развернуть.

## Примеры использования

### Сценарий 1: Вы исправили баг

```bash
git add check_catalog.py
git commit -m "Исправлен баг с множественным числом"
git push origin main
```

**Что происходит:**

1. GitHub Actions запускается автоматически
2. Запускаются все тесты → ✅ Прошли
3. Проверяется форматирование → ✅ OK
4. Проверяется безопасность → ✅ OK
5. Вы получаете уведомление: **✅ All checks passed**

### Сценарий 2: Вы случайно сломали код

```bash
git add check_catalog.py
git commit -m "Обновление логики"
git push origin main
```

**Что происходит:**

1. GitHub Actions запускается автоматически
2. Запускаются тесты → ❌ **Провалено** (тест не прошёл)
3. Вы получаете уведомление: **❌ Tests failed**
4. Открываете логи и видите, какой именно тест сломался
5. Исправляете ошибку и пушите снова

## Как читать результаты CI/CD?

### В GitHub

1. Откройте ваш репозиторий на GitHub
2. Перейдите во вкладку **Actions**
3. Увидите список всех запусков pipeline
4. Кликните на любой запуск, чтобы увидеть детали

### Статусы

- 🟢 **Success** — все проверки прошли успешно
- 🔴 **Failure** — одна или несколько проверок провалились
- 🟡 **In progress** — проверки выполняются
- ⚪ **Skipped** — проверка пропущена

## Как расширить наш CI/CD?

### Добавить автоматическое развёртывание

Можно настроить автоматическую публикацию на сервер при push в `main`:

```yaml
deploy:
  name: Развёртывание на продакшн
  runs-on: ubuntu-latest
  needs: [test, lint, security]
  if: github.ref == 'refs/heads/main'

  steps:
  - name: Деплой на сервер
    run: |
      # Команды для развёртывания
      ssh user@server 'cd /app && git pull && systemctl restart app'
```

### Добавить уведомления в Telegram/Slack

```yaml
- name: Уведомление в Telegram
  if: failure()
  run: |
    curl -X POST "https://api.telegram.org/bot${{ secrets.BOT_TOKEN }}/sendMessage" \
      -d chat_id=${{ secrets.CHAT_ID }} \
      -d text="❌ CI/CD провален для коммита ${{ github.sha }}"
```

### Добавить автоматическое создание релизов

```yaml
- name: Создание релиза
  uses: actions/create-release@v1
  with:
    tag_name: v${{ github.run_number }}
    release_name: Release v${{ github.run_number }}
```

## Часто задаваемые вопросы

### ❓ GitHub Actions платный?

Для **публичных репозиториев** — бесплатно.
Для **приватных** — 2000 минут/месяц бесплатно на GitHub Free.

### ❓ Можно ли запустить CI/CD локально?

Да, с помощью инструмента [act](https://github.com/nektos/act):

```bash
# Установка
brew install act  # macOS
choco install act  # Windows

# Запуск
act
```

### ❓ Как пропустить CI/CD для коммита?

Добавьте в сообщение коммита:

```bash
git commit -m "Обновление документации [skip ci]"
```

### ❓ Как посмотреть логи упавших тестов?

1. Откройте **Actions** в GitHub
2. Выберите упавший запуск
3. Кликните на красный шаг
4. Увидите детальные логи
